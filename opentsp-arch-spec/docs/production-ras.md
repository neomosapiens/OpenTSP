# Serving-domain reliability, availability and serviceability

An application receives a token only after the device step that produced it passes the completion checks. A fault that makes execution untrustworthy terminates every request with live state in that domain. Tokens already delivered remain valid under the fault model below. The client receives an explicit error and can submit a new request. A request still queued entirely on the host can run after recovery.

This platform contract applies to the published TinyStories and GPT-2 serving backends. A TinyStories domain has one chip. A full GPT-2 domain contains one simulated node of 16 chips, including all 12 layer stages, the three head stages and the unused chip slot. A fault on one stage fences the whole node. Serving is synchronous with one device call outstanding per domain. The platform adds no instruction, encoding, CSR or architectural interrupt to specification 0.1. Its recovery policy is an OpenTSP design choice.

## What a chip reports

The core Sail and C harness specify the protected words, ECC decoding, poison, local suppression, scrub, bounded error log and masked interrupt. The ISS management reader takes a second observation at the point the chip records an event. Reading or clearing a guest-visible register cannot erase this observation. Each execution records a saturating event count and fatal count, cause bitmap, log overflow, first event and first fatal architectural record. A typed SRAM location survives only while every fatal report identifies the same physical word. An independent field retains the first pending spare-bit report found by management in raw SRAM. The two-word architectural record encodes queue, cycle, kind, location, superlane and syndrome as specified in the [microarchitecture chapter, sections 15–18](microarchitecture.md).

| Evidence before publication | Serving action | Possible automatic re-entry |
|---|---|---|
| Corrected data, fetched text, matrix or link event; completion and all other checks succeed | Record the event and use the corrected result | Execution continues |
| Uncorrectable SRAM data or check bits traced to one chip, slice and address, with complete evidence | Discard private output, interrupt residents, fence, retain the incident | One cold attempt for that chip and slice |
| Stream poison, uncorrectable fetched text, matrix or link failure, or a consumed spare-bit report | Interrupt and fence | Operator clearance |
| Pending spare-bit report in raw SRAM at the management scan | Interrupt and fence before reading results or retaining the data | Operator clearance |
| Multiple implicated words or chips, fatal evidence with log overflow, incomplete or conflicting diagnostics | Interrupt and fence | Operator clearance |
| Device deadline, process loss, stale reply, incomplete run, missing egress, failed isolation or lost journal | Fail closed | Operator clearance |

**Residual risk: stored poison.** The chip marks an uncorrectable result with poison that a MEM Write stores with the word. A stored poisoned word that suffers one further upset is read by the next consumer as a single-bit error for any single further flip of the 137 code bits except those that give a syndrome above 136; a flip of the spare bit (bit 137) is outside the code, so the word stays uncorrectable and a spare-bit report is added. A data-bit flip, the commonest upset, launders the word as well, and the correction can change a second data bit (the flipped bit and a "corrected" neighbour: two wrong bits, logged as corrected); a check-bit flip changes the data byte. The event is logged as corrected, so the later consumer does not see an uncorrectable word ([microarchitecture §15](microarchitecture.md), "Residual risk: a stored poisoned word"). No choice of poison pattern removes the effect; only a poison bit stored out of band with each word would, and that is a version-level change. The published system relies on a fault plus a software replay of the inference after an uncorrectable error (ISCA22 sections 4.4 and 4.5), not on poison that survives storage, and the serving policy here does the same: the first uncorrectable event already logs, counts and interrupts, and the serving action fences the domain and discards private output without trusting later reads of the poisoned word. A production design that wants poison to survive further upsets must add the out-of-band bit and its qualification.

A data ECC event observed by a stream consumer can have the same architectural kind as a stored SRAM fault. Its consumer location is insufficient to authorize an automatic SRAM repair. Similarly, acknowledging an interrupt reports that software saw a notification. It says nothing about whether an earlier DMA can still reach a buffer.

The native serving binding runs a quiescent integrity scan before raw reads and SRAM-retaining restart. In the ISS, only words with nonzero integrity overlays can contain modelled errors. The scan checks these words with the same decoder as patrol scrub, repairs correctable words and retains evidence of unsafe words. Normal architectural patrol retains its configured arbitration and cycle timing. A physical SRAM has no such sparse oracle. Its implementation requires checked reads, poison propagation and coverage of retained state across reset, or a complete protected scan before exposing or reusing it.

## The publication edge

The companion Sail file `opentsp-arch-spec/platform/ras/commit.sail` specifies write acceptance, participant settlement, result visibility and the conditions for reopening. The synthesizable `ras_commit.sv` supplies the clocked participant mask, acknowledgement register, 64-bit attempt tag, first-fault retention and fence. The component has one in-flight attempt and a 32-bit countdown clocked by the management clock. These platform interfaces operate outside the instruction pipeline.

1. Power-on reset starts fenced. Management can open the fence only with positive isolation, health and policy evidence. Before using an epoch again after power loss, the platform must invalidate old mappings and obtain a fresh drain acknowledgement from every path.
2. Launch latches a nonempty participant mask, a nonzero management-tick budget and advances the tag. Each edge that keeps an attempt active decrements the budget. When one tick remains, expiry wins even over valid completion on that edge. It latches a timeout and fences the domain without a response from the compute clock. A simultaneous external fault retains the external detail. A report counts only for its matching tag. Each asserted member bit attests that the participant finished and that the detectors covering its work have settled. The source must deliver its data and tag atomically across any clock-domain crossing.
3. DMA may write only to private staging assigned to the current active tag. The visibility acknowledgement names the same tag and attests that every expected transfer completed and became observable in order. The last accepted write and publication occur on different edges. An incomplete transfer, stale visibility event or missing member leaves the result private until the conditions are met or the deadline expires.
4. An unsafe event wins over a simultaneous visibility event or release, including when notification is masked. The gate rejects writes, suppresses publication, latches the first fault and fences the domain. The gate stores parity over its control and first-fault state. A parity mismatch blocks both writes and publication immediately and latches mandatory service on the next management edge. Even a valid release command cannot clear this latch. After a cold management reset, the ordinary isolation and health checks apply again. Parity can miss an even number of flips and requires the checker, clock and reset path to function. Tag exhaustion also requires isolation before reuse. A private stage buffer can be recycled only after its old writers lose access.
5. In the ISS service, a private process owns every chip, link, DMA queue and staging buffer. The parent correlates its single outstanding operation by process incarnation and sequence. Frames carry a SHA-256 digest and a checked length. This detects corruption on the trusted private channel. The worker inspects native completion, diagnostics, integrity and output shape before returning the step's logits. On failure the scheduler drops the whole batch, invalidates cached KV prefixes and sends a terminal error for each resident request. A successful recovery admits fresh work only.

The clocked gate is a reference RTL component. The software uses a process boundary and its completion checks. A board port must connect the gates at the actual DMA mapping and public completion points. Resetting the compute queues alone leaves independent DMA, posted writes and peer traffic outstanding.

## Isolation and return to service

The first action is to close admission. The host records the incident and terminates the old ISS process, waiting for confirmed exit. The containment evidence on this backend is destruction of its complete private address space and channels. If that acknowledgement or the journal write fails, the domain stays unavailable. On hardware the driver must disable submissions, restrict bus mastering or revoke DMA mappings, drain or invalidate pending writes, invalidate outstanding peer epochs and obtain acknowledgements from the entire domain. The management path and its deadline must remain functional when the execution clock stops.

Before an automatic attempt, the service durably reserves it in a SQLite transaction. The recurrence key is the chip and SRAM slice. Two failures at different addresses in the same slice can share a physical cause. This policy treats them as recurrent until an operator services the domain. It trades availability for a smaller chance of repeatedly returning a damaged bank to service.

A cold attempt launches an empty device, revalidates programs, metadata and weights, and compares the loaded package identity with that of the healthy startup. It tests the implicated address with byte patterns 00, FF, 55 and AA, checking every read and restoring the freshly loaded value. SHIP runs the address probe on every node member. A private token then runs through the complete model. Its finite logits must match the healthy startup digest bit for bit. Before admission the implementation clears the canary KV. Failure of any step quarantines the entire domain. The canary exercises the workload path and its active links. A passing canary does not establish general arithmetic correctness or screen all SRAM cells and physical links.

## Operations

Configure a stable `additional_config.opentsp.ras_domain` or `OPENTSP_RAS_DOMAIN` for each independent deployment. The default combines the backend name and resolved weight source. Independent replicas sharing weights need distinct, stable domain names. Keep `OPENTSP_RAS_STATE_DIR` on durable local storage with working file locks and synchronous transactions. It defaults to `~/.local/state/opentsp/ras`. Reusing the domain identity across service restarts preserves its recovery budget. Two owners cannot open the same domain concurrently.

`OPENTSP_RAS_STEP_TIMEOUT_S` defaults to 300 seconds per ordinary device call, and `OPENTSP_RAS_LOAD_TIMEOUT_S` to 3600 seconds per create or load call. These are adjustable simulator deadlines, independent of simulated cycles. They are not physical detection, recovery or service-latency specifications. A live but stopped device process times out just as a disconnected process does. The emulator bounds the wait for confirmation of process death to five seconds.

Inspect the history while the service is running or stopped. Stop the service before recording a clearance. Investigate the cause and confirm isolation or repair first.

```sh
python -m opentsp_vllm.ras rack1-node2
python -m opentsp_vllm.ras rack1-node2 --clear "replacement and isolation verified, incident 482"
```

The history preserves timestamps, state transitions, fault location and diagnostic details. The service refuses automatic startup after an unclean shutdown, an interrupted recovery or quarantine. A clearance adds a new record and starts a new service interval. A clean shutdown preserves earlier attempts. Protect this state directory as an operational asset. It is trusted local state and does not authenticate a repair.

The driver-side ordering follows the public distinction between quiescing a domain, resetting it and enabling I/O after coordinated recovery. These stages need positive acknowledgements on the concrete interconnect. [PCI error recovery](https://docs.kernel.org/PCI/pci-error-recovery.html)

## What physical qualification still requires

| Owner | Evidence required for a production chip |
|---|---|
| Chip and memory designers | Macro ECC and interleaving coverage, parity or equivalent protection for addresses, control, queue head/tail, tags and completion bits; results for single, burst, persistent, multi-bit and common-mode faults. Characterize faults that produce valid but wrong codewords, including a further upset of a stored poisoned word (a check-bit flip or a data-bit flip), which reads as a corrected single-bit error unless it gives a syndrome above 136 (above); a spare-bit flip leaves the word uncorrectable and adds a spare-bit report. |
| Interconnect and board teams | End-to-end integrity for data and routing metadata, isolation and drain measured with outstanding DMA and network traffic, segregated management clock/reset/power, reset sequencing, CDC and fault-injection evidence across every participating link. |
| Driver and firmware developers | A protected incident channel surviving device reset, real watchdog and isolation acknowledgements, exclusive domain ownership, mapping revocation, tested interrupt-loss fallback, a validated trust root for production images and a working service procedure. |
| System owners | Measured failure-detection and recovery latency, diagnostic coverage, undetected corruption and repair rates under a declared workload and fault distribution, and service availability against the product target. |

The [validation chapter](validation.md) states the properties checked for the core and the result gate. The serving qualification report gives the fault injections, client observations and reproduction commands for both published backends. Physical qualification, silent-data-corruption rates and fleet availability remain open until measured on the target deployment.
